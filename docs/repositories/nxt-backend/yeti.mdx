# yeti

`yeti` is the time-series data collector and aggregation service.

## Responsibilities

- Periodic telemetry ingestion and snapshot writing to TimescaleDB.
- Snapshot generation for meters, grids, MPPTs, routers, and DCUs across intervals (minute to day).
- Forecasting pipelines (including solar irradiance inputs).
- Grid diagnostics and live digital twin state updates.
- Exchange-rate snapshot collection.

## Ownership boundaries

- Owns telemetry ingestion, aggregation intervals, and time-series outputs.
- Does not own transactional business workflows unrelated to telemetry.
- Shares derived data with other services while preserving Timescale-first processing patterns.

## Interfaces

- Consumes device telemetry and related measurement streams.
- Produces snapshots and aggregates consumed by monitoring/analytics workflows.
- Writes high-frequency data to TimescaleDB and exposes derived outputs to platform services.

## Runtime and operations

- Interval-based collectors and aggregators run continuously at different cadences.
- Data correctness depends on clock alignment, ingestion continuity, and retention policies.
- Monitoring focus: ingestion lag, missing snapshots, processing backlog, and storage growth.

## Failure and edge cases

- Telemetry gaps should be visible and recoverable without silent data corruption.
- Backfills/reprocessing must avoid duplicate aggregates where possible.
